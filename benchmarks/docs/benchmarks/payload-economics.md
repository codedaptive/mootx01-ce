# Payload Economics

## Purpose

This test measures what the rendered payload costs and what evidence it carries.

Retrieval metrics end at the ranked list. They score whether the correct row
was returned. The rows still have to be read by whatever answers the question,
and reading them has a token cost that the ranked list does not express. Two
systems returning the same rows at the same rank can differ by several times in
what it costs to use them.

## Terminology

| This document | System under test |
|---|---|
| database | estate |
| row | drawer |
| exact arm | `moot_memory_search` |
| dense arm | `moot_recall_distilled` |

## Source corpus and artifact

Payload Economics is a MOOTx01-authored instrument over the frozen `lme-s`
questions and gold answers. It reuses the selected port's ready Form-2
`lme-s` artifact. The lane does not generate a separate source corpus or build
a separate estate.

The release `lme-s` corpus supplies a gold answer for every question and
carries `has_answer` turn annotations where evidence is identified. A question
without an annotated evidence turn is counted in `no_evidence`; it is not
converted into an evidence miss.

Its MOOTx01-authored classification describes ownership of the method, not
ownership of the source data.

## Method

Two things are held fixed across every run: the questions and the retrieval
results. Only the payload shape varies.

Payload shapes:

**Preview.** A short extract per returned row.

**Full content.** The complete body of each returned row.

**Compressed.** A reduced form of the returned content produced by the store.

Each shape is rendered from the same frozen retrieval results and scored by
the same mechanical procedure. Scoring is deterministic; no model grades any
payload in this lane.

## Activation arm comparison

Activation arms let the lane test different payload compositions over one
frozen retrieval result. The lane clones the artifact copy-on-write, applies
an activation set to the clone, serves it frozen, and discards the clone after
the run. The original artifact is never modified.

Payload Economics distinguishes two experiments:

1. **Arm value:** one named activation arm is active versus the naked arm
   (no activation). This is ONE retrieval and TWO compositions; ids, order,
   scores, and questions are byte-for-byte shared.
2. **Arm comparison:** each registered arm is activated alone over the same
   frozen retrieval results. Additional arms MAY activate combinations to
   measure zero/one/many behavior.

An arm is identified by the sorted set of active arm IDs recorded at
activation time. The result composer applies the activation, serves the clone,
and restores the original state. No arm copies a Drawer, swaps a canonical
column, or introduces a benchmark-only variant table.

Official runs are isolated from concurrent product composition so every
rendered arm observes exactly its recorded set.

## Metrics

The following figures are computed per payload shape.

**Tokens read** is the mean payload size the shape renders, estimated
deterministically as `(utf8_byte_count + 3) / 4`. The estimate uses no external
tokenizer, so it is stable across runs and across machines.

**Answer presence rate** is the fraction of questions whose payload contains
the dataset's gold answer under normalized substring matching. Gold answers
are available for every release question, so this figure is always reported.

**Answer presence per 1000 tokens** is answer presence rate divided by mean
tokens and multiplied by 1000. It is reported whenever mean tokens are
nonzero.

**Evidence hit rate** applies the same normalized-substring procedure to the
text of `has_answer`-annotated turns. Its denominator contains only questions
with annotated evidence. **Evidence hits per 1000 tokens** scales that rate by
mean tokens. A full-coverage release report contains both fields. A bounded
slice with no annotated question may omit them; omission means unavailable,
never zero.

The exact and dense retrieval arms also report hit@k and MRR through the
artifact ID-map fold. Those retrieval figures describe the ranked results on
which the rendered payload rests.

Adornment-minter arms additionally report generation latency and cost,
generated bytes per Drawer/minter pair, minter-master bytes, adornment-table
bytes per pair, missing-output rate, and between-run answer-presence/token
variance. Evidence variance is included when evidence annotations are
available. These costs are reported separately from the payload figures.

## What is recorded

Per shape, the report carries `mean_tokens`, `answer_presence_rate`, and, when
mean tokens are nonzero, `answer_presence_per_1k_tokens`. A full-coverage
release report also carries `evidence_hit_rate` and
`evidence_hits_per_1k_tokens`; a bounded slice may omit them only when it
contains no annotated question. Retrieval arms carry `hit_at_k` and `mrr`.
The report also carries `no_evidence`, the count of questions without an
evidence annotation, and the ratio between the dense and exact arm token
means. Every report carries the provenance fields required by
`../BENCHMARK_METHOD.md` §6.

For a minter-comparison arm, the report also carries the sorted active-minter
IDs, each referenced minter descriptor, the estate digest, generation-run
identity, and the additional generation/storage figures above. The ordinary
benchmark result artifact records the realized outputs needed to audit that
run; it is not an operational alternative-adornment store.

## Invocation

```sh
make smoke-measure-payload-economics [PORT=swift|rust]
make measure-payload-economics [PORT=swift|rust] [LIMIT=<n>]
```

Run these commands from `benchmarks/`. The wide target requires the selected
port's smoke stamp. Both targets also require the LongMemEval fetch and seed
projection and the selected port's ready Form-2 `lme-s` artifact, prepared as
specified in `../BENCHMARK_RUN_BOOK.md` §9. The artifact dependency is fixed;
the targets do not accept `SCALE`.
