# Authored Benchmark Definitions

Scope: the eight MOOTx01-authored release 1.1 benchmark contracts. Parent
`../AGENTS.md` remains authoritative for command grammar, ports, evidence, and
publication.

| File | Contract |
|---|---|
| `supersession.md` | evolving facts, conflicts, divergence, and decoys |
| `gauntlet.md` | five adversarial distractor classes |
| `journey.md` | multi-step agent work and payload cost |
| `timing.md` | read, write, ingest, and cycle latency |
| `posture-matrix.md` | plaintext/encrypted retrieval equivalence |
| `payload-economics.md` | mechanical gold-answer presence and token cost by payload/minter arm |
| `synthesis-payload.md` | cited synthesized payload as a fourth arm |
| `deterministic-alternatives.md` | judge-free evidence metrics for external data |

Every definition must state purpose, source corpus or corpus construction,
estate shape, metrics, record fields, and the Make invocation. The
`supersession`, `gauntlet`, `journey`, `timing`, `matrix`, and
`deterministic-alternatives` corpora are deterministic and generated by
`make seeds`. `payload-economics` and `synthesis-payload` instead use the
frozen `lme-s` corpus and the selected port's ready Form-2 `lme-s` artifact;
their MOOTx01-authored status describes the instrument, not the corpus.
Internal targets accept `PORT` and `LIMIT`; they do not accept external
`SCALE`, `TOPK`, or protocol judging keys. A definition is portable: do not
make success depend on a feature available only in MOOTx01.

For both payload definitions, gold-answer presence is always available and the
release corpus carries `has_answer` evidence annotations. Full-coverage
release reports require both answer-presence and evidence-hit figures and
their per-1000-token values. A bounded slice may omit evidence fields only when
none of its questions is annotated; `no_evidence` records those questions, and
they are never scored as misses. Retrieval arms carry hit@k and MRR; the
synthesis arm does not.

Do not place measured values, status narratives, or implementation history in
these files. Result values belong to reports and the accepted-results ledger.
