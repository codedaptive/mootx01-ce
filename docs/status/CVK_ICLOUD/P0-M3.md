### docs/decisions/DECISION_CONVERGENCEKIT_CONCURRENT_MULTIDEVICE_2026-07-16.md

**Section changed: N1 — Echo suppression (Requirements block)**

Rewrote the N1 requirement in full per Kong Q2 REWORK adjudication:

- **Replaced** the "engine-internal suppression flag / alternate write
  path; no PersistenceKit type change required" mechanism description
  with the adjudicated mechanism: PersistenceKit stamps `origin`
  (`local | syncApply`) on `TableChange` at write time; ConvergenceKit
  outbox discards `origin == syncApply` events.
- **Added** explicit rejection reasoning for the keyed suppression
  window: (1) SQLiteStorage observer delivery is fire-and-forget
  (`Task { await r.notify(change) }` — unordered, verified in source);
  (2) `TableChange.hlc` is always `nil` in practice on both backends
  (verified in StorageObserver.swift — the field exists but neither
  InMemory nor SQLite constructors pass it); a keyed window therefore
  cannot distinguish an echo from a genuine concurrent same-row local
  edit.
- **Documented** accepted cost: PersistenceKit type extension with blast
  radius; full spec deferred to PERSISTENCEKIT_SPEC.md and P1-M1.
- **Preserved** all other sections verbatim (N2, N3, N4, Rationale,
  Shipped-defect audit, Decision, Playground Rules, Status).

### docs/reference/CONVERGENCEKIT_SPEC.md

**Version bump:** `1.1` → `1.2-draft`

**§ 4 — Invariants: added I-10, I-11, I-12 (marked v1.2-draft)**

- **I-10 (no-echo):** inbound apply never re-enters outbox;
  PersistenceKit-stamped `origin` field; consumer guarantee: local
  writes always ship.
- **I-11 (device slot identity):** registry-assigned `(slot, epoch)`;
  slots 1–15, node 0 reserved; superseded epoch must not push;
  re-enrollment re-mints outbox with fresh HLCs.
- **I-12 (durable pipeline):** outbox and server change token survive
  process death; entries clear on per-record confirmation.

**§ 5 — Behavioral contracts: added B-8 through B-12 and Note N4
(marked v1.2-draft)**

- **B-8 (fieldLevelLWW):** per-column HLC LWW; `columnHLCs` wire field
  (Rust twin per C-8); array/blob columns are atomic whole values.
- **B-9 (tombstoned deletes):** typed tombstones through LWW gate; HLC
  persists in side table post-hard-delete on both backends; `pushOnly`
  caveat (silently swallows remote tombstones).
- **B-10 (schema-skew posture):** newer-schema records held in pending
  queue; older-schema records rejected as conflicts.
- **B-11 (convergence loop):** debounced outbox drain; adaptive tiered
  polling; zone-subscription push is optional accelerator.
- **B-12 (side-table governance):** all `_ck_*` side tables under one
  `SchemaDeclaration`, kitID "ConvergenceKit", single additive version.
- **Note N4 (CloudKit exclusivity):** CloudKit backend is Swift-vertical
  only; wire-format changes still carry Rust twins per C-8; Federation
  is the Rust multi-machine story.

**§ 6 — Error model: added two CloudKit-only rows (marked v1.2-draft)**

- `reenrollRequired(slot:staleEpoch:currentEpoch:)` — per-cycle
  quarantine; engine re-claims slot and re-mints outbox.
- `slotExhausted(activeCount:)` — surfaced loud to caller.
- Updated per-cycle vs. cycle-aborting classification note to include
  both new cases alongside `corruptRemoteIdentity`.

**Changelog entry:** `1.2-draft -- 2026-07-16` added.
