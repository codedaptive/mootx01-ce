## Wire encoding chosen

- Swift: `ColumnHLCMap` is a `Codable` struct with `entries: [String: PackedHLC]`.
  JSON shape: `{"entries": {"colName": {"physicalTime":…,"logicalCount":…,"nodeID":…}}}`.
  Rust: `ColumnHLCMap { entries: BTreeMap<String, PackedHLC> }` — BTreeMap ensures
  alphabetical key order for deterministic encoding (C-8 byte-level parity requirement).

- `SyncRecord.columnHLCs: ColumnHLCMap?` / `column_hlcs: Option<ColumnHLCMap>`.
  Omitted from JSON when nil (`encodeIfPresent` / `skip_serializing_if = "Option::is_none"`).
  Backward compat: nil = row-grain LWW fallback using `SyncRecord.hlc`.

## Commutativity property test description

`FieldLWWMergeTests.mergeCommutativity()`: applies two records A and B in
both orders (A then B, B then A) against an empty initial state. Verifies
that the final `updatedColumnHLCs` map is identical in both paths. The
property holds because `merge()` picks `max(hlcA, hlcB)` per column — max
is commutative and associative.

`ColumnHLCMapTests.mergeCommutativity()`: exhaustive fixed-case table
covering disjoint, A-wins, B-wins, tie, and multi-column-overlapping scenarios.

## Discoveries

- `PackedHLC` lacked `Comparable` conformance — added in `ColumnHLCMap.swift`.
  Extension is on the existing type; cross-module compatible.
- `DecodedRecord` in `CKRecordMapping.swift` had no explicit memberwise init.
  Had to add one after adding `columnHLCs: ColumnHLCMap?` stored property.
- `TableChange` in PersistenceKit does not expose per-column identity (no
  `changedColumns`). This means stamp-all-present is the only correct approach
  until PersistenceKit gains this. Logged in Discoveries for future mission scope.
