## Discoveries

- Worktree was cut before P1-M0 (engine decompose), P1-M5 (token persistence),
  P1-M8 (fix) merged to develop/1.1.x. Resolved by committing PK changes first
  then merging develop/1.1.x. Pattern to note: wormhole worktrees cut against
  stale base are a recurring gotcha on rapidly developing branches.

- SQLite observer delivery is fire-and-forget Task-based (unordered). The keyed
  window approach for echo suppression was evaluated and rejected because
  Task ordering is not guaranteed. Origin tag at write time is the correct
  mechanism since it stamps before the Task is spawned.

- Rust federation already has working echo suppression via pulling:Arc<AtomicBool>
  flag in EngineState. Rust observer delivery is synchronous (mpsc channel,
  worker threads), not async Tasks, so the flag is sound there. The ChangeOrigin
  field in Rust is API parity only — the actual suppression continues to use
  the pulling flag. insert_sync/upsert_sync/delete_sync Rust defaults correctly
  delegate to ordinary write paths.

- CachingRowStore required careful handling: insertSync/upsertSync/deleteSync
  overrides must include all the cache-invalidation logic from the ordinary paths
  (key extraction, cache clear, backing store delegation). This was verified by
  the cachingRowStore_insertSync_preservesSyncApplyOrigin and
  cachingRowStore_deleteSync_preservesSyncApplyOrigin tests.

- applyInbound never calls update (only upsert, insert, delete). updateRows on
  both backends does NOT carry the origin parameter — confirmed by reading
  all four conflict-policy branches.
