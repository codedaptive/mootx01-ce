# CVK-ICLOUD Tracked Follow-Ups

Items deferred from the 30-mission CVK-ICLOUD program. Each entry
names what, why it was deferred, where it lives, and a suggested scope
for the follow-up mission.

| # | Item | What | Why deferred | File / location | Suggested scope |
|---|---|---|---|---|---|
| 1 | **Tier-rise retraction (Perkins A2)** | When a synced row's sensitivity tier rises above the ceiling after initial sync, the current implementation suppresses further outbound changes but does NOT emit a retraction tombstone to peers that already received the row. Peers retain the last-synced snapshot. A "emit delete CKRecord for rowKey" path is needed in `CloudKitSyncEngine`. | Requires a new outbound delete path that bypasses the normal outbox flow; out of scope for P5-M1 sensitivity gate. | `apps/Mootx01-App/Sources/MootGateway/Sync/SensitivityFilteredStorage.swift` (Perkins Finding 1, Amendment 2); `packages/kits/ConvergenceKit/Sources/ConvergenceKitCloudKit/` | Tier-1 new capability in ConvergenceKitCloudKit: add a `retractRow(table:rowKey:)` path that emits a tombstone CKRecord without going through the outbox observer. Scope: ConvergenceKitCloudKit + SensitivityFilteredStorage caller. |
| 2 | **In-app sync toggle (Simms verdict 1)** | Users should be able to enable or disable iCloud sync from the app settings. The engine supports `enable`/`disable` but there is no UI surface for it. | UI scope was deferred post-P5 as a separate settings mission. | `apps/Mootx01-App/Sources/GatewayUI/EngineView.swift` | UI-bounded mission: add a toggle to EngineView; wire through SyncController.enable/disable; surface sync state via existing SyncState enum. |
| 3 | **CKRecord.encryptedValues eval** | CloudKit supports `encryptedValues` for end-to-end encrypted field storage. The current `CKRecordMapping` uses plain `CKRecord` values. Evaluating whether sensitive LocusKit fields (e.g. diary content, high-sensitivity drawers) should use `encryptedValues` is an open security question. | Perkins flagged as advisory (not blocking); no consensus on which fields should be encrypted vs. visible to the CloudKit dashboard. | `packages/kits/ConvergenceKit/Sources/ConvergenceKitCloudKit/CKRecordMapping.swift` | Research spike: compare CKRecord.value vs CKRecord.encryptedValues for each TypedValue case; evaluate performance and dashboard debuggability cost. Outcome is a decision record, not necessarily code. |
| 4 | **TableChange.changedColumns (PersistenceKit)** | `fieldLevelLWW` currently stamps ALL present value columns with the capture HLC, because `TableChange` does not carry a `changedColumns` set. When `TableChange` gains `changedColumns` support, outbox entries for `fieldLevelLWW` tables can stamp only the actually-changed columns per capture, reducing outbound column HLC map size. | Requires a PersistenceKit schema change (`TableChange` struct expansion); blast radius crosses the substrate boundary. | `packages/kits/PersistenceKit/` — `TableChange` type; `packages/kits/ConvergenceKit/Sources/ConvergenceKitCloudKit/Engine/CloudKitStateActor.swift` `recordOutbound` and `packages/kits/ConvergenceKit/Sources/ConvergenceKitFederation/FederationSyncEngine.swift` `recordOutbound` | Primitive-touching mission: add `changedColumns: Set<String>?` to `TableChange` with nil = all columns; update SQLite + InMemory stores to stamp it on update events; update ConvergenceKit outbox observer to use it when non-nil. |
| 5 | **Outbox secondary index + readSyncHLC batch-read** | Scorandum Q3 identified that `OutboxStore.readBatch` does a full table scan when filtering by `is_parked = 0`. A secondary index on `(kit_id, is_parked, id)` would reduce push-cycle overhead for large outbox depths. Q5 identified that the tombstone LWW gate reads `_ck_sync_meta` per-row; a batch-read helper could reduce round-trips for multi-record pull cycles. | Schema migration scope and blast radius require a dedicated primitive-touching mission. | `packages/kits/ConvergenceKit/Sources/ConvergenceKit/Outbox/OutboxStore.swift`; `packages/kits/ConvergenceKit/Sources/ConvergenceKitCloudKit/CKSideSchema.swift` | Primitive-touching mission: add index in `SideSchema` migration at next version bump; add `readSyncHLCBatch(rowKeys:)` to `CKSyncMetaStore`. Must carry tests for both. |
| 6 | **Scheduler retryableBackoff wiring** | When a push cycle receives `CKError.requestRateLimited` with a `retryAfterSeconds` value, `AdaptivePollScheduler` should delay future pull cycles by at least that duration to avoid hammering a throttled endpoint. The seam (`recordThrottled(retryAfterMs:)` on `PollTierPolicy`) is in place but not yet wired from `CKErrorTaxonomy` through to the scheduler. | Implementation requires a coordination channel between `OutboxDrainDebouncer`/push path and the poll scheduler actor; deferred to avoid cross-actor coupling in P3-M2. | `packages/kits/ConvergenceKit/Sources/ConvergenceKitCloudKit/Engine/AdaptivePollScheduler.swift` (`recordThrottled` seam comment); `packages/kits/ConvergenceKit/Sources/ConvergenceKitCloudKit/Engine/CloudKitStateActor.swift` | Tier-2 mission: wire `CKErrorTaxonomy.retryableBackoff(retryAfter:)` result from push cycle through to `AdaptivePollScheduler.recordThrottled`; add test asserting next poll interval respects the server floor. |
| 7 | **TombstoneGC production scheduling** | `TombstoneGC` is implemented and tested but is not yet scheduled in the production app flow. In the current app wiring, GC is never invoked automatically — tombstones accumulate indefinitely. | Scheduling requires deciding the trigger (enable-time, periodic background task, or pull-cycle hook); deferred post-P5 to avoid app-tier scope in the kit missions. | `packages/kits/ConvergenceKit/Sources/ConvergenceKit/TombstoneGC.swift`; `apps/Mootx01-App/Sources/MootGateway/SyncController.swift` | App-tier mission: add a scheduled GC call in `SyncController` (e.g. after each successful pull cycle if `receipt.pulled > 0`); configure retention window; add a telemetry counter for rows GC'd. |
| 8 | **Benchmark lane placement** | The `CVK_ICLOUD_P4M5_PerfTests.swift` perf benchmarks run in the main kit test suite, pushing the total `swift test` time to ~77 s. These benchmarks should be isolated into an env-gated or `.serialized` target so fast-path CI remains sub-30 s. | Benchmark placement requires a `Package.swift` change that creates a conditional target; out of scope for the perf mission. | `packages/kits/ConvergenceKit/Tests/ConvergenceKitCloudKitTests/CVK_ICLOUD_P4M5_PerfTests.swift`; `packages/kits/ConvergenceKit/Package.swift` | Tooling mission: move perf benchmarks to a `ConvergenceKitBenchmarkTests` target gated on `ENABLE_PERF_BENCHMARKS=1` environment variable; update Makefile to run benchmarks in a separate lane. |
| 9 | **Rust fieldLevelLWW column-grain parity** | Swift ships `fieldLevelLWW` end-to-end (outbound stamp, inbound apply, `FieldLWWMerge`, `ColumnHLCStore`). The Rust port ships the wire types (`ColumnHLCMap`, `SyncRecord.column_hlcs`) and the JSON encoding (C-10 wire parity) but does NOT ship the apply-side logic in `FederationSyncEngine`. Rust Federation sync with `fieldLevelLWW` tables currently falls back to row-grain LWW. | Rust apply-side requires `ColumnHLCStore` equivalent and integration with the Rust `apply_record` path; separate mission to avoid mixing Swift engine work with Rust engine work. | `packages/kits/ConvergenceKit/rust/src/federation.rs` (`apply_record` function); `packages/kits/ConvergenceKit/rust/src/types.rs` | Rust-vertical mission (Newton lane): implement `ColumnHLCMap`-aware apply in `apply_record` for `FieldLevelLWW` policy; add `_fed_sync_meta_cols` equivalent in Rust side schema; port `FieldLWWMerge` logic to Rust. |
| 10 | **Federation durable outbox/drain** | Federation uses an in-memory `pendingOutbound: [TableChange]` array rather than a durable SQLite outbox. Changes are lost on process death. For persistent cross-machine sync, Federation should adopt the same durable outbox pattern as the CloudKit backend (`_fed_outbox` table; `OutboxStore`). | Scope is large (new side table, migration, drain logic, echo suppression on restart); deferred as Federation's in-process relay is the current production target. | `packages/kits/ConvergenceKit/Sources/ConvergenceKitFederation/FederationSyncEngine.swift` (`pendingOutbound` array); `packages/kits/ConvergenceKit/Sources/ConvergenceKit/Outbox/OutboxStore.swift` | Tier-1 primitive-touching mission: add `_fed_outbox` durable side table; replace `pendingOutbound` with `OutboxStore`-backed drain; ensure echo suppression on reload (outbox entries are pre-stamped as `.local` origin). |
| 11 | **SyncValueBox depth hard-limit** | `SyncValueBox.array` is recursive — an array of arrays of arrays. No current enforcement bounds the nesting depth. A malformed inbound record could produce a deeply nested `SyncValueBox` that exhausts the stack on recursive decode. Defense in depth: cap decode depth at 3 levels (matching LocusKit's actual usage). | Advisory from Perkins review; no exploit vector in the current closed-channel Federation/CloudKit flow, but defense-in-depth is warranted. | `packages/kits/ConvergenceKit/Sources/ConvergenceKit/SyncRecord.swift` (`SyncValueBox` decode); `packages/kits/ConvergenceKit/rust/src/record.rs` (`SyncValueBox` serde decode) | Small additive mission: add `maxDepth: Int = 3` parameter to `SyncValueBox.fromJSON` (Swift) and a recursive depth counter to the Rust serde deserializer; add test that a 4-level array returns `.decodingFailure`. |

| 12 | A11 side-table consolidation: fold `_ck_device_identity` into `CKSideSchema` (last holdout; earmarked version superseded by fieldLevelLWW v6) | Single SchemaDeclaration governance (SPEC B-12) | `Sources/ConvergenceKit/DeviceRegistry/DeviceIdentityStore.swift` | Small kit mission: move declaration, bump CKSideSchema version, keep read/write helpers |
