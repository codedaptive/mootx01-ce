## Conflicts Between 9 Original Rules and Shipped Reality

Five places where the architectural rules describe design intent that is
not yet fully implemented in the shipped code in this worktree:

1. **Rule 3 — post-apply integrity hook mechanism not shipped.**
   The rule cites a `postApplyIntegrityHook` on `SyncManifest` (R3). The
   shipped `SyncManifest.init(kitID:schemaVersion:zoneIdentifier:tables:)` has
   no such parameter. The hook is v1.2-draft. Shipped workaround documented
   in the example.

2. **Rule 4 — column projection mechanism not shipped.**
   The rule cites `excludedColumns` on `SyncedTable` (R2). The shipped
   `SyncedTable.init(name:direction:primaryKeyColumn:conflictPolicy:)` has no
   `excludedColumns` parameter. The mechanism is v1.2-draft. Shipped workaround
   documented in the example.

3. **Rule 6 — tombstoned LWW delete gate not fully implemented in shipped
   `CloudKitSyncEngine`.**
   The rule states "Deletes are tombstoned LWW." SPEC B-4 specifies an HLC gate
   on deletes. However, shipped `CloudKitSyncEngine.swift` line 328 (D2 defect)
   calls `delete(...)` with no HLC comparison. The delete always applies
   regardless of HLC ordering. B-9 (tombstone side-table persistence after
   hard-delete) is v1.2-draft. The rule describes the target state, not the
   shipped behavior.

4. **Rule 8 — version skew "pauses" sync; shipped behavior "rejects as
   conflict".**
   The rule states "A schema mismatch holds newer-version records in a pending
   queue." The shipped behavior (SPEC I-4, v1.0.0 of this worktree's SPEC) is:
   schemaMismatch rejects the record as a conflict and counts it in the receipt.
   No queue exists. B-10 (the pending queue) is v1.2-draft. The rule describes
   the v1.2-draft design intent.

5. **Rule 7 — N2 slot registry prerequisite not yet shipped.**
   The rule's HLC ordering guarantee depends on unique node IDs per device
   (N2 slot registry, v1.2-draft). Shipped `CloudKitSyncEngine` draws
   `Int32.random(in: 1...0x0F)` per launch (D4 defect in the audit). Two
   devices can share a node ID with probability ≈1/15 per session pair,
   producing undefined HLC ordering. The guarantee is conditional on N2, not
   unconditional.
