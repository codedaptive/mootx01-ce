## Scenarios Implemented

1. **Slot exhaustion** — 15 devices claim slots 1-15 via CAS; 16th active claim throws
   `.slotExhausted(activeCount: 15)`. Loud failure, no silent overflow.

2. **Eviction + epoch bump** — 16th device triggers eviction of oldest-inactive slot
   (35-day phantom, 2026-scale HLCs with 40-bit truncation regression territory, packed
   round-trip via masked physicalTime). Eviction succeeds; new slot assigned; epoch bumps.

3. **Critical fencing scenarios (3 parts)**:
   - (3a) Evicted device returns with stale (slot, epoch) → `EpochFence.heartbeat` throws
     `reenrollRequired` at step 3b, BEFORE any record reaches CloudZoneFake. Zero records
     in cloud post-fence. Loud, early.
   - (3b) Re-enrollment remints outbox; all reminted HLCs strictly > pre-eviction HLCs
     (A2 ordering guarantee); new nodeID on every entry.
   - (3c) Full engine integration: epoch bump → push auto-reenrolls → remints → B
     converges; all CKRecords in cloud carry new nodeID in `_syncHLC` (verified via
     CKRecordMapping.packed() bit extraction: nodeID in bits 3-0).

4. **CAS race** — concurrent CAS attempts on an exhausted registry; exactly one winner
   per slot, no two active devices share a nodeID.

5. **LWW ordering after evict+reclaim** — B's stale write (T2) loses to A's post-re-enroll
   write (T3); both estates resolve identically (LWW soundness).

6. **Ghost fast-path** — `lastActiveHLC == HLC.zero && claimedAt > 1 hour ago` → evictable;
   recent ghost and heartbeated-active device → not evictable.

## Discoveries

**Two HLC packing formats in play**: `HLC.packed` (outbox entries, SubstrateTypes) puts
nodeID in bits 63-56 (8-bit field). `CKRecordMapping.packed()` (CKRecord `_syncHLC` field)
puts nodeID in bits 3-0 (4-bit field, layout: physical 48 | logical 12 | node 4). Scenario
3c required a separate helper `ckRecordNodeIDOf()` extracting bits 3-0 for CKRecord
assertions, vs `p4m3NodeIDOf()` for outbox entry assertions (bits 63-56). This distinction
is load-bearing — confusing the two produces silently wrong nodeID assertions.

**40-bit truncation is real at 2026 scale**: Unix-ms (~1.75e12) exceeds 2^40 (~1.10e12).
Scenario 2 required masking BOTH sides of the inactivity comparison with `& 0xFF_FFFF_FFFF`
(already implemented in SlotTable.evictionCandidate; verified the scenario exercises the
masked path without regression).
