|---|---|---|

## Tag-Map Field Shape

Field name: `_syncTypeTags`
Wire type: NSString (CKRecord field)
Content: JSON-encoded `[String: String]` mapping column name → discriminator name
Discriminator names: `"uuid"`, `"bitmap"`, `"hlc"`, `"json"`, `"fingerprint"`
Example: `{"id":"uuid","digest":"fingerprint","row_hlc":"hlc"}`
Auto-filtered: field starts with `_sync` → excluded from the `values` dict in decode

## Defects Found and Fixed

1. **Missing `try` on `engine.disable()`** in `TwoEstateFixture.restartEngine(_:storage:)`:
   `CloudKitSyncEngine.disable()` is declared `async throws`; the P4-M1 code called it
   with `await` only. Added `try` — compile error if not fixed.

2. **Fault consumed by slot heartbeat before data push**: `CloudZoneFake.modifyRecords`
   consumed a queued fault on the first `modifyRecords` call regardless of record type.
   The slot heartbeat (all `_ck_device_slot` records) consumed the `.partialBatchFailure`
   fault before the data push, causing the partial-failure scenario to see no fault on
   the data records. Fixed by adding `hasDataRecords` guard: fault injection only runs
   when the batch contains at least one non-slot record. Slot-only batches are transparent
   to the data-push fault queue.

3. **`OutboxStore.insertEntry` inaccessible from test module**: The test suite only had
   `@testable import ConvergenceKitCloudKit`. `insertEntry` is internal to `ConvergenceKit`.
   Fixed by adding `@testable import ConvergenceKit`; and replaced `insertEntry` with
   the public `OutboxStore.append(entry:to:)` which has identical behaviour when the
   outbox is empty (no existing entry for the (table_name, row_key) key).
