## Discoveries

- **Rust PersistenceKit API uses builder constructors throughout** — `ColumnDeclaration::text("name")`, `TableDeclaration::new(name, cols, pk)`, `SchemaDeclaration::new(kit_id, version, tables)`; struct literals would fail on hidden fields (e.g. `role: None`). Future Rust migration missions: always grep `schema.rs` and `storage.rs` before writing schema code.

- **Rust HLC packing layout differs from Swift** — Rust: `(8-bit node << 56) | (16-bit logical << 40) | (40-bit physical)`. Swift: `(48-bit physical << 16) | (12-bit logical << 4) | (4-bit node)`. Both use `packed()` as the method name but the layouts are not interchangeable. Side tables in each backend store HLC from their own backend only — no cross-backend HLC comparisons are needed.

- **InMemory PersistenceKit accepts extra columns on upsert** — schema declared with three columns; upsert with six columns (including side-table-like extras) works. This is why tests can call `ensureSyncMetaTable` as a migration on the same InMemory store without a conflict.

- **`isTombstone` on `DecodedRecord` is `public var`** (not `let`) — test-level construction pattern works by building a normal `DecodedRecord` then flipping `.isTombstone = true`. This was necessary because `DecodedRecord` lacks a convenience tombstone initializer that sets all fields correctly.
