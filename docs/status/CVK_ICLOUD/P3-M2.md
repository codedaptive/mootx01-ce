## What Was Done

### Part 1 — PollTierPolicy (pure tier decision table)

**File:** `Sources/ConvergenceKit/Loop/PollTierPolicy.swift`

Pure adaptive tier decision table with no OS time calls. `nowMs: Int64`
injection makes the full transition table deterministically testable.

| Tier | Interval | When |
|---|---|---|
| `fast` | 20 s | Recent remote or local activity |
| `mid` | 90 s | Activity receding; zone calming |
| `idle` | 5 min | Zone quiescent; conserve quota |

Activity window: 2 minutes. Empty pulls within the window HOLD fast tier
(prevents oscillation when a remote device is still writing between polls).

Public mutation methods: `recordNonEmptyPull(nowMs:)`, `recordEmptyPull(nowMs:)`,
`recordNudge(nowMs:)`. All named constants have WHY comments (CloudKit quota
math, battery budget rationale).

### Part 2 — AdaptivePollScheduler (poll loop actor)

**File:** `Sources/ConvergenceKitCloudKit/Engine/AdaptivePollScheduler.swift`

Swift 6 `actor` that owns the adaptive poll loop:
- Injected `SchedulerPullFn` and `SchedulerSleepFn` closures for testability
- `start()` idempotent; `stop()` deterministic (satisfies SPEC I-2)
- `nudge()` — interrupts the current sleep via sub-task cancellation WITHOUT
  cancelling the main loop task; fires an immediate pull and resets tier to fast
- `currentTier` and `nextIntervalMs` for diagnostic surfaces

Sleep interruption mechanism: the sleep runs in a `Task<Void, Never>` child
(`_sleepTask`). `nudge()` cancels only `_sleepTask`; the loop's
`await _sleepTask.value` returns immediately and the pull fires.

CKError backoff (planned P3-M4): comment seam in `runLoop()` identifies where
`max(intervalMs, throttleFloorMs)` will be inserted when `CKErrorTaxonomy`
`.retryableBackoff` wires in.

## Discoveries

- **Swift 6 actor isolation for non-async methods**: calling actor-isolated
  `start()` and `stop()` from outside the actor requires `await` even though
  the methods are not declared `async`. Fixed in both production code
  (`CloudKitSyncEngine.enable()` / `disable()`) and test code.
- **`defer` blocks are synchronous**: in Swift 6 strict concurrency, `defer`
  blocks cannot contain `await`. Integration tests that need async cleanup
  (calling `scheduler.stop()`) must do it explicitly at the end of the function.
- **Parallel swift-testing runner + instant-sleep schedulers**: two integration
  tests with `sleep: { _ in }` schedulers running concurrently starve each
  other's `Task.yield()` loops. Mitigated by marking the integration test suite
  `.serialized`.
- **`public struct` memberwise init is `internal`**: Swift's implicit memberwise
  init for `public struct PollTierPolicy` is `internal`, not `public`. Added
  explicit `public init()` to make it constructible from `ConvergenceKitCloudKit`.
- **`PullCycle.pull()` appliedCount semantics**: every record that passes through
  `applyInbound` without throwing increments `appliedCount`, even if the LWW
  gate determines the record is not newer. This means `pulled` counts records
  _attempted_, not records that changed local state. The scheduler correctly
  treats this as activity signal.
