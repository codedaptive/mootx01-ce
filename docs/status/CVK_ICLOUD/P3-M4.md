## Discoveries

- **SideSchema v7 not v5**: The mission spec mentioned "planned v5" in prior docs.
  The actual CKSideSchema version at mission start was v6 (v3→v6 jump happened in P2-M1).
  The `_ck_pending_skew` table lands at v7 via a clean v6→v7 migration. Updated B-12 in
  SPEC to reflect the actual v7 landing.

- **Federation replay vs CloudKit replay**: CloudKit's `applyInbound` takes `DecodedRecord`,
  requiring `SyncRecord.asDecodedRecord()` at replay time. Federation's `applyInbound` takes
  `SyncRecord` directly — no conversion needed. Both paths echo-suppress correctly.

- **Subscribe timing in tests**: Swift's `AsyncStream` subscription (via `engine.subscribe()`)
  launches a Task to call `stateActor.attachSubscriber`. If the test calls `pull()` before
  that task runs, events are lost (no subscriber registered yet). Yielding 30+ times after
  subscribe and before the block resolves this. Added comment in `collectEvents` helper.

- **Task closure concurrency (Swift 6)**: Capturing a local `var [SyncEvent]` in a `Task`
  is a strict-concurrency violation. Resolved with `EventCollector` actor in the test file.
