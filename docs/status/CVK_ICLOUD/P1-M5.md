# CVK-ICLOUD P1-M5 — Persisted server change token (R5)

**Status:** COMPLETE
**Stream:** CVK-ICLOUD
**Requirement:** R5 from DECISION_CONVERGENCEKIT_OPERATIONAL_SYNC_2026-06-09.md

## What was done

- Added `Sources/ConvergenceKitCloudKit/Engine/TokenStore.swift`: persists
  `CKServerChangeToken` per zone in a new `_ck_change_token` side table.
  Round-trip via `NSKeyedArchiver(requiringSecureCoding: true)` because
  `CKServerChangeToken` is `NSSecureCoding`, not `Codable`.

- Wired into `CloudKitStateActor.enable()`: calls `TokenStore.ensure(storage:)`
  to create the side table, then `TokenStore.load(zoneName:storage:)` to
  restore the persisted token so the first pull resumes where the last
  one left off.

- Wired into `CloudKitStateActor.pull()`: after every successful pull,
  calls `try? TokenStore.save(token:zoneName:storage:)` to persist the
  new token. Save failure is non-fatal (worst case: redundant full-zone
  pull on next launch).

- Wired `CKError.changeTokenExpired` handling in `pull()`: clears the
  persisted token via `TokenStore.clear(zoneName:storage:)`, resets
  `serverChangeToken = nil`, and re-pulls from scratch. Safe because
  `applyInbound` is idempotent under all four conflict policies.

- Added `Tests/ConvergenceKitCloudKitTests/TokenStoreTests.swift`: 11 new
  tests covering archiver round-trip (NSString stand-in for
  CKServerChangeToken, which has no public initializer), per-zone keying
  independence, expiry-reset state transitions, and idempotent ensure.
