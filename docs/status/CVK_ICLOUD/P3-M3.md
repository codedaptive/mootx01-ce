## Host-App Contract Summary

1. Declare `com.apple.developer.icloud-services` → CloudKit entitlement.
2. Call `UIApplication.registerForRemoteNotifications()` (or AppKit equivalent).
3. After `engine.enable()` succeeds, call `engine.registerZoneSubscription()`.
   Safe to repeat on every launch (subscription ID is deterministic).
4. In `application(_:didReceiveRemoteNotification:fetchCompletionHandler:)`:
   ```swift
   Task {
       let consumed = await engine.handleRemoteNotification(userInfo: userInfo)
       handler(consumed ? .newData : .noData)
   }
   ```
5. To unsubscribe (e.g. before disabling the engine): call
   `engine.deregisterZoneSubscription()`.

The kit does NOT call UIApplication or NSApplication. The resident launchd
process (which holds no APNs entitlements) builds unchanged — new files import
only Foundation and CloudKit.

## Discoveries

- The previous INTERFACE doc listed `registerZoneSubscription(database:)` with
  a `CKDatabase` parameter (from an earlier draft before the seam was in place).
  The actual shipped API takes no database arg — the seam resolves it. Updated
  the doc accordingly.
- `@Suite("...", .serialized)` is the correct Swift Testing serialized-suite
  syntax. The earlier draft used `@Suite.serialized` as a separate attribute,
  which is not valid — fixed in the final test file.
- `defer { Task { try await f() } }` generates "unstructured throwing task not
  used" warnings. Correct pattern is explicit `try? await engine.disable()` at
  the end of each test (not in defer), matching `AdaptivePollSchedulerTests`.
