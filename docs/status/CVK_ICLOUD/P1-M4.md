### Part 3 — OutboxStore.swift

New file `packages/kits/ConvergenceKit/Sources/ConvergenceKit/Outbox/OutboxStore.swift`.
Stateless enum with four operations:
- `append(entry:to:)` — coalescing insert: newest-wins by packedHLC on
  (table_name, row_key) key; stale writes are no-ops
- `readBatch(from:limit:)` — read WITHOUT consume; entries survive until
  confirmed; ordered by HLC ascending (oldest-first for retry determinism)
- `confirm(ids:from:)` — delete only the listed IDs (transport-success path)
- `drainLeftovers(from:)` — enable-time scan for prior-process survivors

### Part 4 — CloudKitSyncEngine.swift wired to durable outbox

Modified `packages/kits/ConvergenceKit/Sources/ConvergenceKitCloudKit/CloudKitSyncEngine.swift`:
- Removed `var pendingOutbound: [TableChange] = []`
- `enable()`: calls `CKSideSchema.ensure(storage:)`, then
  `OutboxStore.drainLeftovers(from:)` and logs leftover count
- `disable()`: removed `pendingOutbound.removeAll()` (outbox survives in DB;
  observation tasks are still torn down before return)
- `recordOutbound(_:)`: changed to `async`; mints HLC at observe time;
  encodes values via `SyncValueMap` + `JSONEncoder`; calls
  `OutboxStore.append(entry:to:storage)` with error-logged-not-thrown contract
- `push()`: reads batch via `OutboxStore.readBatch`; decodes each entry;
  builds CKRecord; tracks `confirmedIDs`; calls `OutboxStore.confirm(ids:from:)`
  only on transport success; throws on failure WITHOUT confirming (entries
  survive for retry)
- `ensureSyncMetaTable` now delegates to `CKSideSchema.ensure(storage:)`;
  private constant `syncMetaTable` aliases `CKSideSchema.syncMetaTable`

## Discoveries

**Federation in-memory pattern:** FederationStateActor has the identical
R4 defect (pendingOutbound array, removeAll before push). Not in scope for
this mission per decision docs. Flagged in Note N4 for a future mission.

**HLC minted at observe time:** moved from push() to recordOutbound(). HLC
now represents logical ordering at change-capture time, not at push time.
This is the correct semantic — two changes captured before the next push
retain their observed ordering in the outbox.

**_ck_sync_meta schema continuity:** existing `ensureSyncMetaTable` called
CKSideSchema.ensure via a delegation wrapper so old installs with
_ck_sync_meta already on disk continue to work (PersistenceKit
migrate-to uses IF NOT EXISTS throughout).

**Worktree structure difference:** worktree has monolithic
CloudKitSyncEngine.swift where develop/1.1.x has Engine/ subdirectory.
Adapted Edit calls to the monolithic file with exact string matching.

in the session. The file is not in the git repo (wrong path base) and has
