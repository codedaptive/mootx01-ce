## Discoveries

1. **[AnyHashable: Any] region-isolation in Swift 6**: Forwarding actor-isolated
   `[AnyHashable: Any]` to a non-isolated async method fails the Swift 6 region-isolation
   checker because `Any` is not `Sendable`. Fixed with an `@unchecked Sendable` wrapper
   struct + `Task.detached`. The assertion is valid: CloudKit push userInfo contains only
   ObjC bridge types (NSString, NSDictionary, NSNumber) which are thread-safe. Pattern
   worth noting for any future actor→class notification forwarding.

2. **SyncTileView tier display deferred**: `AdaptivePollScheduler.currentTier` is not
   exposed in `CloudKitSyncEngine`'s public surface (`_schedulerBox` is private, no
   `currentTier` accessor). The tile shows container ID and last-sync timestamp only.
   A follow-up can add a `currentTier` public property to `CloudKitSyncEngine` if the
   diagnostic value justifies the surface area.

3. **Package.swift test dep addition not in BRR**: Adding `ConvergenceKitCloudKit` to
   the `MootGatewayTests` target in Package.swift was needed for `@testable` parser access.
   This is a small additive change not flagged in the blast radius report (no production
   symbol changes, test-target only). Noted here for completeness.

4. **`moot-mgr` name disambiguation**: The mission phrase "moot-mgr (the Mac app)" is
   ambiguous — three processes carry similar names (`apps/moot-mgr` CLI, `apps/mootx01`
   daemon, `apps/Mootx01-App` SwiftUI app). ZoneSubscription.swift line 7 is the
   authoritative disambiguation: "host-app processes (moot-mgr, Mootx01-App)" means the
   Mootx01-App SwiftUI process. Future missions should use "Mootx01-App" explicitly.
