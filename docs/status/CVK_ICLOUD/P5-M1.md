## What Was Done

### Part 1 — SensitivityFilteredStorage (Perkins Gate)

New file: `apps/Mootx01-App/Sources/MootGateway/Sync/SensitivityFilteredStorage.swift`

Implements the consumer-side sensitivity ceiling wrapper per Perkins Finding 1.
ConvergenceKit stays estate-type-free; the wrapper lives in MootGateway (estate layer).

**Outbound gate:** `SensitivityFilteredObserver` wraps `StorageObserver.observe()` and
drops `TableChange` events where `adjective_bitmap` bits 6-11 encode a sensitivity tier
above `syncCeiling`. The engine's outbound observer never sees above-ceiling events; they
never enter the outbox and never cross the CloudKit wire.

**Inbound gate:** `SensitivityFilteredRowStore.insertSync()` / `upsertSync()` throw
`SensitivityCeilingError` when the inbound record's `adjective_bitmap` exceeds the
ceiling. PullCycle's per-record catch counts the throw as a conflict. The row is not
written locally.

**Tombstone forwarding:** `deleteSync` is forwarded unchanged. Tombstone CKRecords carry
only row identity (UUID + delete HLC), not content. Filtering tombstones would prevent
deletion signals from propagating to local storage.

**Tables without adjective_bitmap** (tunnels, kg_facts, diary) pass both gates unchanged.

**Perkins Amendment 1 invariant documented:** The `SensitivityFilteredStorage` instance
MUST be the EXACT handle passed to `engine.enable()`. Comment in both
`SensitivityFilteredStorage.swift` (file header) and `SyncController.enable()` explains
why — `AppliedBatch.storage` (IntegrityHook.swift:56) IS the handle the engine holds;
bypassing the wrapper lets hook-repair writes on restricted rows carry `origin == .local`
and enter the outbox.

## Discoveries

**Tier-rise retraction (Perkins Amendment 2) — tracked follow-up:**
When a previously-synced row's sensitivity tier rises above the ceiling, peers retain
the last-synced snapshot. P5-M1 ships outbound suppression only (no new changes escape).
Retraction requires emitting a delete CKRecord for the row, which requires a new path in
CloudKitSyncEngine. Tracked as follow-up. Documented in SensitivityFilteredStorage.swift
file header.

**encryptedValues evaluation (Perkins Finding 1, advisory):**
CKRecord.encryptedValues was evaluated for P5-M1 scope. Conclusion: deferred. Encrypted
field values in CloudKit require all participating devices to be on the same iCloud account
or sharing a CKShare with encrypted encryption. Implementing correctly for a multi-device
estate requires CloudKit container key management that is out of scope for this wiring
mission. Documented as tracked follow-up.

**GeniusLocusKit.registerSyncEngine was NOT previously called:**
The `sync:` field in `moot_estate_status` was returning `"local-only"` even when the
CloudKit engine was active (because `registerSyncEngine` was never called). P5-M1 fixes
this: `SyncController.enable()` now calls `bridge.registerSyncEngine()` immediately after
`engine.enable()`, so the status surface reports the real backend + state.

**MootBridge now retains kit+handle:**
Previously `makeDispatcher` created `GeniusLocusKit` and `EstateHandle` locally and
discarded them (ToolDispatcher held its own copies). To support `registerSyncEngine`,
MootBridge now retains both. The refactor is clean: `makeComponents` returns a
`BridgeComponents` struct rather than just the dispatcher.

## Estate Configuration — Consumer Quick Reference

Enable iCloud sync in the app at launch:
```swift
await MootSyncDriver.shared.configure(.cloudKitDefault)
```

Disable sync (administrative override):
```swift
await MootSyncDriver.shared.configure(.disabled)
```

Custom ceiling (sync restricted rows too):
```swift
let config = SyncConfig(
    backend: .cloudKit(containerIdentifier: MootSyncDriver.containerIdentifier),
    syncCeiling: .restricted,  // restricted rows now sync; secret rows still gated
    enabled: true
)
await MootSyncDriver.shared.configure(config)
```

The default (`.disabled`) ships safely without any iCloud entitlement or container.
