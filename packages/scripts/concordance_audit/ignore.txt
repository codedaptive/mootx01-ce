# Concordance-audit ignore-list
# ------------------------------
# Format:  <Name> | <reason>
# One bare top-level type name per line (the audit matches on the bare name,
# so a name listed here is exempt in EVERY package — keep names specific).
#
# POLICY (see README.md): this list is for types that legitimately CANNOT
# have a Swift<->Rust concordance row because they are platform-bound (an
# Apple-only framework binding with no Rust counterpart) or are dev/test
# fixtures, not contract surface. It is NOT a way to silence real drift.
# A missing concordance row for a genuine cross-port contract type is real
# work to be done in a per-kit mission, not an ignore-list entry. Keep this
# list short and justified; every entry states why no row can exist.

# --- Apple-only CloudKit bindings (ConvergenceKitCloudKit target) ---
# CloudKit is an Apple framework. The CloudKit sync backend is Swift-only by
# design (ConvergenceKit exposes CloudKit/Federation/None behind one protocol;
# only Federation/None have Rust ports). These types have no Rust counterpart.
CloudKitSyncEngine | Apple-only CloudKit backend; no Rust port by design
CKRecordMapping | Apple-only CKRecord<->row mapping; no Rust port by design
DecodedRecord | Apple-only CKRecord decode helper in CloudKit target
SyncMeta | Apple-only CloudKit sync-metadata type in CloudKit target

# --- Apple-only Metal GPU kernel (SubstrateKernel) ---
# MetalKernel is the Apple Silicon GPU compute path. Metal is a system
# framework with no Rust equivalent; the Rust port uses scalar/BLAS/NEON.
MetalKernel | Apple-only Metal GPU kernel; Rust uses scalar/BLAS/NEON path

# --- ADR-017 architectural idiom differences ---
# Swift organizes schema declarations via protocol/enum types (Ops, Schema,
# Tables); Rust handles the same concern via inline module structure. These
# are not contract surface — they are language-specific patterns for the same
# underlying tables. No Rust counterpart will ever exist with this name.
ErasureLedgerOps | Swift schema-organization protocol; Rust uses inline module
ErasureLedgerSchema | Swift schema-organization enum; Rust uses inline module
ErasureLedgerTables | Swift schema-organization enum; Rust uses inline module
SnapshotRegistryOps | Swift schema-organization protocol; Rust uses inline module
SnapshotSchema | Swift schema-organization enum; Rust uses inline module
SnapshotTables | Swift schema-organization enum; Rust uses inline module

# Rust-only observer dispatcher. Swift uses the StorageObserver actor pattern
# for the same fan-out concern. The names differ because the concurrency
# models differ (Rust: explicit Hub struct; Swift: actor + async sequences).
DirtyChainHub | Rust-only observer dispatcher; Swift uses StorageObserver actor
